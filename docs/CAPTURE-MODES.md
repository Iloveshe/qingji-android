# 无通知采集、自动 OCR 和悬浮窗

## 如何开启

1. 覆盖安装 0.1.2；不要卸载旧版。已安装 0.1.1 可使用“应用更新 → 立即检查更新”，保持接收测试版开启。
2. 轻记设置中开启“支付窗口自动 OCR（无通知）”，阅读并同意说明。它也会启用“支付页面文字”，但系统无障碍权限仍需自行授予。
3. 在系统无障碍中关闭再开启轻记，以重新加载更新后的截图能力。已授权的普通页面文字功能仍然可用。
4. 勾选云闪付，正常付款或打开单笔付款详情。设置中的页面状态可判断最近处理结果；识别结果可能在“账单”或“待确认”。
5. 如需悬浮状态，再开启“悬浮采集状态”，授予“显示在其他应用上层”。两项功能独立；悬浮窗本身不提供读取其他 App 的能力。

## 来源与边界

| 来源 | 无交易通知可用 | 是否需要显示页面 | 条件 |
| --- | --- | --- | --- |
| 页面文字 | 是 | 是 | 无障碍、选定 App、可读节点 |
| 自动窗口 OCR | 是 | 是 | Android 14+、额外开启、无障碍截图能力；云闪付窗口或其他选定 App 的交易结果提示 |
| 银行交易短信 | 是 | 否 | 有实际收到的交易短信，开启短信权限与来源白名单 |
| 临时录屏 OCR | 是 | 是 | 每次系统录屏授权、前台运行通知 |
| 付款详情截图分享 | 是 | 图片即可 | 手动分享或导入单张图片 |

本实现没有接入云闪付、微信、支付宝后台账户或银行开放接口，也没有取得小米系统签名权限。小米钱包的公开隐私说明只确认其经授权读取其他 App 账单，没有公开其具体采集实现，不能据此认定它只靠通知、悬浮窗或某个私有系统接口。

参考：[小米钱包隐私说明，第 15–16 页](https://ts.market.mi-img.com/download/MifiMp/00716170e48d34b47af403e56c0ffe277a1777175/%E9%92%B1%E5%8C%8520.pdf?_external=true)、[Android 无障碍窗口截图接口](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback))。

## 实现保护与去重

- 截图绑定选定的具体窗口，不使用全屏截图作为自动降级；其他 App 的聊天、键盘或通知栏不进入该窗口的 OCR 图片。
- 锁屏、窗口或包名变化、服务关闭、取消 App 勾选、开关关闭后，未完成的截图和 OCR 结果丢弃。检测到可编辑或密码节点、遍历超限时不截图；受系统保护的窗口不绕过限制。
- 每 4 秒最多截图一次，同一页面最多 3 次，已解析出交易的节点不重复做 OCR。连续页面内容变化不会像旧版那样一直推迟首次读取。
- 图片资源及时释放，不生成截图文件。诊断仅保存固定状态文字和时间，不保存页面正文、图片或密码。
- 保持原有交易去重：账户互转不计收支，同金额不能单独合并，订单冲突待核对。自动 OCR 也保留历史日期；缺少日期或商户不会直接确认。
- 增加“交易成功”“扣款 / 扣费”“商户全称”“商户单号”格式；一般“交易成功”没有方向时待确认，不能猜成支出。“收款方”字段不再误当成收入动词。

## 待实机验证

Android SDK 编译与纯 Java 策略测试无法替代 Redmi 实机验证。需检查 HyperOS 无障碍截图是否授权成功、云闪付具体版本的页面结构、动画和二维码付款跳转、系统安全窗口限制、悬浮窗显隐 / 拖动 / 授权撤销，以及切换窗口和锁屏时的异步结果丢弃。字段不足仍进入待确认，不能承诺所有交易都免核对。
