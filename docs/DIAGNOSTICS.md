# 脱敏诊断与截图证据

0.1.3 根据微信 OCR 误记 5999.00 的反馈增加诊断与凭证核对。尚未拿到该次原始画面，因此不能断言已复现具体误识别。新规则拦截无付款凭证特征、无金额标记的数字，OCR 候选不再自动计入收支。

## 导出排查

1. 覆盖安装，保留原账本；在系统无障碍中关闭再开启轻记。
2. 首次提示选择“开启截图证据”，或在“设置 → 数据与诊断”开启。只保存之后匹配到交易的 OCR 输入图；不会补抓旧交易。
3. 进入支付 App 的单笔付款详情，点按悬浮窗左侧识别。右侧“账本”进入待确认。
4. 交易详情 → 查看交易证据与采集截图 → 查看采集截图。支持缩放、拖动。截图是采集时画面，不是根据摘要重建。
5. 漏记时，“查看采集诊断”可以检查权限、服务、截图能力、页面跳过原因；“脱敏日志导出与远程诊断 → 预览 / 导出”生成 JSON 文件。无接口也可使用。

截图用 Android Keystore 的 AES-GCM 密钥加密，存于应用私有、排除备份的目录，不写入公共相册，不提供外部可读 URI。只有本机查看时解密，不随诊断上传。保留原始 OCR 输入画面，可能含余额、卡号等隐私；查看窗口禁止系统截图。总上限 100 MB，单图 12 MB，满后保留账单并提示图片未保存，不静默删除已有截图。可单独清除所有截图而保留账单。

通知、短信和无障碍文字来源没有截图。旧版没有保存的历史截图无法恢复，证据页会直接说明。图库导入的大图可能按 OCR 内存限制采样，保留的是本次 OCR 输入图，不包含源图片 EXIF。

## 可选远程配置

没有内置或部署好的公共日志服务。默认关闭，未配置接口不会上传。将来在设置中填写自己控制的 HTTPS 接收地址和可选 Bearer 令牌，主动勾选并保存后才会启用。地址不允许用户名密码、查询参数、片段；令牌经 Keystore 加密。关闭或清除配置会取消周期任务。

系统 JobScheduler 约每 15 分钟尝试发送一次最近 32 条状态，要求可用网络，可能因 HyperOS 后台限制而延迟。也可点击向已保存的接口发送一次。连接、读取各有 8 秒超时，不跟随重定向、不上传图片、不使用云端模型。

接收接口约定：

- HTTPS `POST`，`Content-Type: application/json; charset=utf-8`。
- 可选 `Authorization: Bearer <你配置的令牌>`，不写入 URL。
- 请求体最多 64 KiB，返回 2xx 表示接收成功，其他状态视为失败；App 不显示或保存服务端响应正文。
- 接收端应自行认证和限制访问，不要使用公共 GitHub Issues 收集日志。

预览、导出和网络发送使用完全相同的白名单 JSON：`schema`、应用版本、Android API、采集开关，以及最多 32 条事件。事件字段为采集时间、来源类别、平台类别、阶段码、规则码、金额提取规则名、商户字段是否存在、是否有完整交易时间、是否待确认。

不含金额值、金额哈希、商户、卡号或尾号、订单号或其哈希、设备型号 / 设备标识、安装标识、短信 / 通知 / OCR 正文、截图、API 密钥和任意异常消息。来源及阶段也经过枚举白名单；无法识别的字段只发送 `OTHER` / `STATUS_ONLY`，不依赖正则“脱敏”原文。

## 覆盖升级

数据库从版本 1 迁移到 2，仅添加截图引用与缺图说明。原账单、金额、时间、商户、人工编辑和忽略记录保留。对于旧版未经人工核对、且只有 OCR 图片来源支持的已确认交易，退回待确认；有短信或通知等其他来源支持的记录不因迁移变动。请核对那笔不存在的 5999.00 后选择“忽略”，不要清空或卸载整个账本。

现有诊断能够区分采集 / 触发 / 识别阶段，但不含原文，所以不能仅靠脱敏包还原具体字体或金额误读。需要时在本机查看截图核对。
